# saucedust

이미지를 올리면 원본이 어느 게시물인지 찾아 주는 역검색 시스템입니다.
Danbooru를 통째로 수집해 벡터로 바꿔 두고, 질의 이미지의 벡터와 가장 가까운
것을 돌려줍니다. 잘리거나 다시 압축되거나 크기가 바뀐 사본도 찾습니다.

여러 대의 컴퓨터에 노드로 나눠 돌릴 수 있습니다. 중앙 노드 한 대가 결과를
모으고 검색을 받고, 나머지는 수집과 계산만 합니다.

실행 방법은 [RUNNING.md](RUNNING.md)에 있습니다. 이 문서는 무엇이 어떻게
생겼고 왜 그렇게 정했는지를 다룹니다.

## 하는 일과 하지 않는 일

수집한 게시물마다 이렇게 남깁니다.

| 남기는 것 | 어디에 | 왜 |
|---|---|---|
| 벡터 | Qdrant와 PostgreSQL | 검색용. PostgreSQL 쪽은 Qdrant가 날아갔을 때 다시 세우기 위한 사본 |
| pHash, dHash | PostgreSQL | 벡터가 비슷하다고 한 것 중 정말 같은 그림인지 가르는 데 씀 |
| 태그, 등급, 점수, 크기 | PostgreSQL | 결과를 보여주고 걸러 내는 데 씀 |
| 384픽셀 축소본 | 노드의 디스크 | 모델을 바꿨을 때 다시 내려받지 않기 위한 최소 사본 |

원본 이미지는 저장하지 않습니다. 1,000만 장이면 수십 테라바이트입니다.
축소본만 두면 같은 수를 수백 기가바이트로 감당하면서, 모델을 갈아 끼워도
Danbooru를 다시 훑지 않고 벡터만 다시 계산할 수 있습니다.

## 구성

```
                    ┌──────────── 중앙 노드 (control) ────────────┐
  브라우저 ────────▶ │  HTTP API  ·  웹 대시보드  ·  텔레그램 봇   │
  텔레그램 ────────▶ │                                             │
                    │  PostgreSQL   Qdrant   임베딩 워커          │
                    └──────────▲──────────────────────────────────┘
                               │ 벡터와 메타데이터
              ┌────────────────┼────────────────┐
        작업 노드          작업 노드         작업 노드
     (수집 + 계산)      (수집 + 계산)     (수집 + 계산)
              │                │                │
              └────────────────┼────────────────┘
                               ▼
                          Danbooru
```

노드는 PostgreSQL에서 ID 구간을 하나 빌려 그 범위를 수집하고, 끝나면 반납합니다.
빌리는 순간 다른 노드는 같은 구간을 가져갈 수 없으므로 일이 겹치지 않습니다.
노드가 죽으면 심장박동이 끊기고, 중앙 노드가 그 구간을 회수해 다시 내놓습니다.

## 폴더

```
cmd/saucedust/        명령줄 진입점과 조립
internal/domain/      개념과 규칙. 아무것도 의존하지 않음
internal/app/         유스케이스와 포트(인터페이스)
internal/adapter/     포트의 실제 구현
internal/config/      환경값 읽기와 검증
python/worker/        임베딩 워커
scripts/              빌드와 검증
```

의존 방향은 한 방향입니다.

```
cmd  ──▶  adapter  ──▶  app  ──▶  domain
```

`domain`은 PostgreSQL도 HTTP도 모릅니다. 해밍 거리, 벡터 정규화, 어떤 게시물을
건너뛸지 같은 규칙만 있습니다. `app`은 인터페이스만 알고 구현은 모릅니다.
그래서 저장소를 바꾸거나 다른 사이트를 붙일 때 규칙을 건드리지 않아도 되고,
시험할 때 진짜 DB 없이 가짜를 꽂을 수 있습니다.

어댑터는 여덟 개입니다.

| 어댑터 | 하는 일 |
|---|---|
| `postgres` | 이미지, 벡터 사본, 구간 임대, 노드 상태 |
| `qdrant` | 벡터 색인과 근사 최근접 검색 |
| `danbooru` | 게시물 목록과 이미지 내려받기, 속도 제한 |
| `embedworker` | 같은 노드의 Python 워커 호출 |
| `netpath` | 직접, ECH, 조각내기, 프록시 중에서 되는 경로 고르기 |
| `filestore` | 축소본 보관 |
| `httpapi` | HTTP API와 대시보드 |
| `telegram` | 봇 |

## 왜 이렇게 정했는지

### 모델을 두 종류 씁니다

같은 그림 찾기와 비슷한 그림 찾기는 다른 일입니다.

- **copy**: 잘리고 다시 압축된 같은 그림을 찾습니다. 역검색의 본체입니다.
- **semantic**: 분위기나 구도가 비슷한 다른 그림을 찾습니다.

한 모델로 둘 다 하려면 어느 쪽이든 나빠집니다. 모델마다 Qdrant 컬렉션을
따로 두므로 나중에 하나만 갈아 끼울 수 있습니다.

수집을 크게 시작하기 전에 어느 copy 모델을 쓸지 정해야 합니다. 나중에 바꾸면
쌓인 것을 전부 다시 계산해야 합니다. `python/worker/benchmark.py`로 비교할 수
있습니다.

### 벡터로 좁히고 해시로 가릅니다

벡터 검색은 "비슷한 것"을 잘 찾지만 "같은 것"과 "닮은 것"을 구분하지 못합니다.
그래서 벡터로 후보를 추린 다음 pHash 해밍 거리로 다시 세웁니다.
64비트 기준 5비트 이내면 사실상 같은 그림으로 봅니다.

실측에서 원본을 절반 크기로 줄이고 JPEG 품질 40으로 다시 저장한 사본의
거리가 2였습니다.

### VPN 대신 TLS 인사말을 조각냅니다

한국 회선에서 `danbooru.donmai.us`는 직접 붙지 못합니다. 다만 막는 방식이
TLS 인사말에 적힌 도메인 이름을 보는 것이라, 그 부분이 한 조각에 담기지
않게 나눠 보내면 통과합니다.

2026년 8월 2일 LG유플러스 회선 실측입니다.

| 경로 | 결과 |
|---|---|
| 직접 | 막힘 (연결 끊김) |
| ECH | 못 씀 (서버가 설정을 내놓지 않음) |
| 조각내기 | **통과. 197밀리초, HTTP/2** |
| CDN 직접 | **애초에 안 막힘. 65밀리초** |

이미지 자체는 CDN에서 오는데 CDN은 막혀 있지 않습니다. 막힌 것은 목록을
가져오는 API뿐이고 그것도 조각내기로 통과합니다. **VPN이 필요 없습니다.**
프록시 주소를 넣는 경로는 대비책으로만 남겨 뒀습니다.

### 진짜 병목은 상대 서버의 속도 제한입니다

네트워크도 GPU도 아니었습니다. 동시 요청을 32까지 올리자 429가 쏟아졌습니다.
Danbooru는 IP 단위로 제한하므로 한 노드에서 더 세게 밀어도 소용이 없습니다.
노드를 늘리는 것이 답입니다.

기본값은 초당 5회, 동시 16개입니다. `Retry-After`를 그대로 따릅니다.
계정을 넣으면 한도가 올라갑니다.

### 계산은 GPU 먼저

CUDA, MPS, CPU 순으로 고릅니다. CUDA에서는 fp16을 쓰고 배치를 크게 잡습니다.

준비 단계(디코드와 축소)는 CPU를, 추론은 GPU를 씁니다. 둘을 같은 스레드
묶음에 두면 서로 자리를 뺏으므로 각자의 몫을 정해 뒀습니다. 추론은 짧게
모아 배치로 넘깁니다.

M1 Pro 실측으로 순수 추론 58장/초, 전체 흐름 50~53장/초입니다.

## 만들고 검증하기

```bash
go build -o saucedust ./cmd/saucedust
```

```bash
./scripts/verify.sh
```

서식, 빌드, `go vet`, staticcheck, gosec, govulncheck, 경합 검사를 켠 Go 시험,
ruff, mypy, Python 시험을 차례로 돌립니다. 저장소나 컨테이너가 필요한 검사는
환경값이 없으면 건너뛰었다고 분명히 알립니다. 조용히 넘어가지 않습니다.

노드에 올릴 실행 파일을 만들려면 이렇게 합니다.

```bash
./scripts/build_nodes.sh
```

macOS와 리눅스, arm64와 amd64 네 가지가 나옵니다. C 의존성을 끄고 만들므로
어느 배포판에나 그대로 올라갑니다.

`cmd`를 뺀 모든 Go 패키지에 시험이 있습니다. `cmd`는 조립과 명령 해석만
합니다.

## 필요한 것

- Go 1.25.5 이상. 그 아래 판에는 표준 라이브러리 취약점이 있습니다
- Python 3.11 이상
- PostgreSQL 16 이상
- Qdrant

준비는 `saucedust setup`이 대신 합니다. 가상 환경을 만들고 torch를 깔고
모델 가중치까지 받아 둡니다. 확인만 하고 싶으면 `saucedust doctor`를 쓰십시오.
